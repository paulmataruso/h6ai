# Audit: h6ai file index and admin (src/_h6ai/public)

Date: 2026-10-22 · Build: h6ai v1.0.0+aa94de49 · Target: http://172.16.1.67:8687 (compose service)

## Evidence and method

- **Detector, rendered:** `impeccable detect --json` on `/`, `/docs/`, `/images/`, `/empty/` and `/_h6ai/public/`, at 1280x800 and 390x844, using headless Chrome 131 (no-sandbox wrapper). 0 findings.
- **Detector, source:** run on `public/css`, `public/js/lib` and `private/php/pages`. 5 `broken-image` warnings. All 5 are false positives: they are runtime templates whose `src` is set by JS (info panel, preview, brand mark, row icons).
- **axe-core 4.10.2:** tags wcag2a/aa, 21a/aa, 22aa and best-practice, run in Chromium 1148 (Playwright 1.49.1). States scanned:
  - index and expansion band in all 5 themes;
  - selection, settings drawer, image preview, filter with no match, empty folder, login dialog;
  - anon denied view and anon menu;
  - admin: all 5 tabs, all 4 access views, checker result, the user, group and rule dialogs, and the access view in 4 more themes;
  - mobile 390: index, band, drawer.
- **Performance:**
  - CDP `Performance.getMetrics` and a sampling CPU profile on `/many/` (151 rows), `/docs/` and `/big/`;
  - served sizes with gzip.
- **Responsive:**
  - overflow scan at 320, 360, 390, 600, 768 and 1024, with the band and preview open;
  - 200% root font size at 390 and 1280;
  - touch: raw CDP touch drag on the list (emulated mobile Chromium) and a touch drag on the size slider.

## Implementation Integrity Verdict

**Pass.** The UI expresses one coherent, product-specific system.

- **Colour:** every colour flows from the generated theme tokens (`themes.css`).
- **Reserved accent:** the download/selection accent appears only on the download path, as the specified Download chip, band button, archive button and notice. Links and primary non-download actions use `--link` and `--action`.
- **Detector:** zero rendered findings on 10 page/viewport combinations. All 5 source findings were checked and are false positives.
- **Bans:** no ban from the craft floor is present. There is no gradient text, no side-tab borders, no hero metrics and no glyph icons.

## Executive Summary

## Detailed Findings by Severity

### [P1] Home breadcrumb link has no accessible name
- **Location:** `css/layout.css` (`#crumbbar .crumb-item:first-child .label {display:none}`); crumb template in `js/lib/ext/crumb.js`.
- **Category:** Accessibility.
- **Impact:** Screen readers announce "link, /" with no name. This is the main way back to the root.
- **WCAG:** 2.4.4, 4.1.2 (axe `link-name`, serious; every index state).
- **Recommendation:** Hide the label visually but keep it in the accessibility tree, or set `aria-label="Home"` on the first crumb.
- **Suggested command:** /impeccable polish.

### [P1] Admin selects without accessible names
- **Location:** `js/lib/main/info.js`:
  - access checker principal select;
  - rule dialog `.grant-row select[name=principal|level]`;
  - activity filters `select[name=user|kind]`.
- **Category:** Accessibility.
- **Impact:** These controls are announced as unnamed combo boxes, so permission rules can't be set reliably with a screen reader.
- **WCAG:** 1.3.1, 4.1.2 (axe `select-name`, critical).
- **Recommendation:** Add `aria-label`s: "Principal", "Access level", "User", "Event type", and "Check as" for the checker.
- **Suggested command:** /impeccable polish.

### [P1] Download chip contrast on a selected row
- **Location:** `css/view.css`, where `#items .dl` sits over `.item.selected > a.main`.
- **Category:** Accessibility.
- **Impact:** In midnight, the chip's size text is #a98dfb on #3c355c, which is 4.25:1. That fails body-text contrast exactly on the rows the user just picked.
- **WCAG:** 1.4.3 (axe `color-contrast`, serious).
- **Recommendation:** On selected rows, put the chip on `--bg-elev-2` (or `--bg`) so the accent text keeps its AA pair. Add the selection-stacked pair to the theme checker.
- **Suggested command:** /impeccable polish.

### [P2] Invalid list semantics: `aria-sort` on links, `role=region` on the band `li`
- **Location:**
  - `js/lib/ext/sort.js:58-59`;
  - `js/lib/ext/expand.js` (band template);
  - `js/lib/view/view.js` (`ul#items role=list`).
- **Category:** Accessibility.
- **Impact:**
  - The sort state is never announced: `aria-sort` is only valid on column headers.
  - The open band breaks the list structure, so item counts are announced wrong.
- **WCAG:** 4.1.2 (axe `aria-allowed-attr`, critical; `aria-required-children`, critical; `aria-allowed-role`).
- **Recommendation:**
  - Make the sort headers real `<button>`s that carry their state in the name ("Name, sorted ascending").
  - Keep the band as a plain `li`, with the region on an inner element.
- **Suggested command:** /impeccable polish.

### [P2] Admin page has no main landmark; empty headings
- **Location:** `js/lib/main/info.js` (`render`, `header`, table heads).
- **Category:** Accessibility.
- **Impact:**
  - There is no landmark to jump to.
  - The `h1` is empty on the login view.
  - The action columns have empty `<th>`.
- **WCAG:** 1.3.1 (axe `landmark-one-main`, `region`, `empty-heading`, `empty-table-header`).
- **Recommendation:**
  - Give `#content` `role=main` on the admin page.
  - Always render "Admin" in the h1.
  - Label the action columns "Actions" (visually hidden).
- **Suggested command:** /impeccable polish.

### [P2] Band command lines scroll without keyboard access
- **Location:** `css/view.css` (`.band-line dd code`), `js/lib/ext/expand.js`.
- **Category:** Accessibility / Responsive.
- **Impact:** Below about 600px, long URLs and curl lines scroll sideways. Keyboard users can't scroll them, although Copy still works.
- **WCAG:** 2.1.1 (axe `scrollable-region-focusable`, serious).
- **Recommendation:** On narrow screens, wrap the lines (`overflow-wrap:anywhere`) instead of scrolling them.
- **Suggested command:** /impeccable adapt.

### [P2] Large folders lay out every row
- **Location:** `css/view.css` (`#items .item`).
- **Category:** Performance.
- **Impact:** `/many/` (151 rows) cost 390ms of layout and 344ms of style recalculation on load, and the sort click took 525ms. This was measured with software rendering, but the cost grows linearly up to `view.maxEntries` = 20000.
- **Recommendation:** Apply `content-visibility:auto` with `contain-intrinsic-size` to the details/list rows, so offscreen rows skip layout and paint.
- **Suggested command:** /impeccable optimize.

### [P2] Size slider is a 16px touch target
- **Location:** `css/panels.css` (`input[type=range]`).
- **Category:** Responsive.
- **Impact:** The drawer's size slider is 307x16 on touch. It does work under a touch drag (0 → 7), but it is hard to grab.
- **WCAG:** 2.5.8.
- **Recommendation:** Give it `min-height: var(--target)` on coarse pointers.
- **Suggested command:** /impeccable adapt.

### [P2] Reduced motion is a global kill
- **Location:** `css/base.css:182`.
- **Category:** Accessibility.
- **Impact:** The 0.01ms rule also freezes the busy pulse ("Preparing…") and the preview spinner. That is useful state feedback, not decoration.
- **Recommendation:**
  - Drop translate and scale entrances, and keep opacity.
  - Slow the spinner rather than stopping it.
  - Swap the pulse for a static busy style.
- **Suggested command:** /impeccable animate.

### [P3] Sort headers are `<a href="#" role="button">`
- **Location:** `js/lib/view/view.js` (header template).
- **Category:** Accessibility.
- **Impact:** Space doesn't activate them; only Enter does.
- **Recommendation:** Use real `<button>`s. This is fixed together with the P2 sort-state item.
- **Suggested command:** /impeccable polish.

### [P3] Preview close button overflows at 320px; drag-select churn
- **Location:**
  - `css/preview.css` (`#pv-bar`);
  - `js/lib/ext/select.js` (`selectionUpdate`, plus a dead `pointerType` check in a mouse handler).
- **Category:** Responsive / Performance.
- **Impact:**
  - The close button sits 7px offscreen on 320px devices.
  - Drag-select restyles every row on every mousemove.
- **Recommendation:**
  - Let the bar shrink with `min-width:0` and hide the low-value items under 360px.
  - Throttle `selectionUpdate` with rAF.
- **Suggested command:** /impeccable polish.

### [P3] Shadow literals outside the token set
- **Location:** `css/controls.css:64`, `css/view.css:510`.
- **Category:** Theming.
- **Impact:** Two `rgba(0,0,0,…)` shadows don't follow a theme's `--shadow*` tokens. They are invisible in today's themes, but would drift in a new one.
- **Recommendation:** Use `--shadow-sm` and `--shadow`.
- **Suggested command:** /impeccable polish.

### Not product defects (verified)
- `image-alt` on `/docs/` and `/visible/` comes from the XSS fixture `_h6ai.header.md` (`<img src=x>`). It is test content, sanitized as intended.
- The detector's 5 source `broken-image` findings are runtime templates.
- Under 200% text, the band's `<code>` lines clip by design: they scroll, and wrapping them is tracked in P2 above.

## Patterns & Systemic Issues

- **Accessible names:** they are missing where a label is visual-only (crumb, admin selects, empty headers). There was no systematic "every control has a name" check until this axe pass. Add the axe scan to the E2E suite.
- **ARIA on non-semantic structure:** `#items` is a `ul` styled as a table. Sort state and inserted rows must respect list semantics rather than borrow table ARIA.

## Positive Findings

- **Detector:** zero rendered findings across 5 pages × 2 viewports.
- **Contrast:** all 5 themes pass every token AA pair in the checker. The only contrast failure is the selected-row stack, which the checker doesn't yet cover.
- **Keyboard:**
  - logical Tab order: brand → crumbs → tools → tree → rows;
  - Enter opens the band with focus on Download, and Esc returns focus to the row;
  - admin tabs and access subnav follow the WAI-ARIA tabs pattern: arrows, Home/End, roving tabindex.
- **Responsive:**
  - no horizontal overflow from 320 to 1024;
  - 200% text reflows;
  - touch drag scrolls the list (1016px) without starting drag-select.
- **Payload:** 78 KB gzipped JS and 11 KB CSS, served `immutable` with a version query. Thumbnails use `loading=lazy`. TTFB on `/many/` was 55ms.
- **States:** the three click modes (expand, download-other, download) and the anon account behave as specified, with no console errors.
